# Epic E3.2 — Face + Hands Refinement

## Scope

E3.2 completes the remaining face/hands portion of Epic E3 for anonymous same-video character tracks. It builds on E2.2 anonymous person tracking and E3.1 COCO-17 body pose.

In scope:
- per-frame face landmarks suitable for geometric motion constraints;
- per-frame left/right hand landmarks;
- explicit presence/quality signals and dense time-series sidecars;
- schema-valid Blueprint references, provenance, reports, and later debug overlays;
- an approved, offline-first refinement runtime after its exact model artifacts are approved and hash-locked.

Out of scope:
- face recognition, face identity embeddings, identity matching, or real-person identification;
- age, health, emotion, sexual-attribute, or other sensitive-attribute inference;
- 3D body pose reconstruction;
- person masks, point tracks, dense flow, camera motion, body-local surface motion, and micro-motion (later Epics);
- silent interpolation or hallucinated fill for missing landmarks.

## Contract-first gate

The canonical schema currently exposes `Face.landmarks_3d_ref` but no face-specific 2D landmark reference, while `HandTrack` already distinguishes `landmarks_2d_ref` and `landmarks_world_ref`.

E3.2 MUST NOT store image-plane face landmarks in `landmarks_3d_ref` merely to avoid a schema change. Before runtime integration:

1. Add optional nullable `Face.landmarks_2d_ref` using `TimeSeriesRef`.
2. Preserve `Face.landmarks_3d_ref` for data whose coordinate semantics are genuinely 3D.
3. New E3.2 producers that emit the added field use Blueprint `schema_version: 1.1.0`; the updated validator remains able to validate existing 1.0.0 manifests.
4. Disabled face state explicitly emits `landmarks_2d_ref: null`.
5. Contract tests reject invalid coordinate-space/shape metadata rather than relying only on JSON type validity.

## Proposed sidecar contract

### Face

Primary 2D landmark array:
- format: `npz`
- dtype: `float32`
- shape: `[frame, face_landmark, xy]`
- axes: `["frame", "face_landmark", "xy"]`
- unit: `px`
- coordinate_space: `pixel_xy`
- missing frame: NaN XY
- interpolation_policy: `none`
- nan_policy: `preserve`

Presence/confidence data must be stored separately or in clearly named arrays with `coordinate_space: none`; confidence values must not be encoded as a fake geometric coordinate.

If a selected runtime exposes a relative-depth `z`, it must be documented as model-relative depth and must not be mislabeled `camera_xyz` or `world_xyz` unless a calibrated transform actually exists.

### Hands

For each of `left` and `right`:
- 2D image-plane landmarks: `[frame, 21, 2]`, `pixel_xy`, float32, NaN when absent;
- present/confidence: `[frame]`, coordinate space `none`;
- optional world landmarks only when the approved runtime explicitly provides that semantic output and its coordinate convention is recorded;
- handedness is a detector classification signal, not identity information.

No temporal interpolation is introduced in E3.2. Missing observations remain explicit.

## Association rules

- Face/hands are attached only to an existing anonymous `character_id` from E2.2.
- E3.1 pose may be used as a geometric prior for face/hand ROIs and left/right association.
- No cross-video identity association is permitted.
- Ambiguous multi-person/multi-hand association must fail transparent: lower coverage / warning / missing observation rather than guessed reassignment.

## Runtime approval gate

No real face/hand model executes merely because a package can be imported.

Before certification, record for every runtime model/artifact:
- exact upstream source;
- exact model/runtime version;
- license record;
- local artifact filename;
- full SHA256 where a standalone model artifact exists;
- configuration hash;
- approved project scope.

Production path remains offline-first and fail-closed. No runtime network download and no fallback model substitution.

## Implementation gate

1. Add the backward-compatible canonical schema field and disabled-manifest wiring.
2. Add positive/negative contract tests for face 2D references and coordinate semantics.
3. Add deterministic injected-backend unit/integration tests before real model certification.
4. Add face/hands stages only when complete configuration is present; partial configuration is a hard failure.
5. Dense arrays stay outside `blueprint.json`; refs contain URI, hash, shape, axes, unit, coordinate space, frame coverage, NaN/interpolation policy, and array-key metadata.
6. Sidecar writes are atomic before the stage is marked `succeeded`.
7. Standard CI, E2 RTMDet certification, and E3.1 RTMPose certification must remain green.
8. A separate real-runtime E3.2 certification workflow must pass before E3.2 is marked runtime-certified.

## Certification acceptance

The final E3.2 certification must prove, on a real authorized/non-sensitive human sample:
- E2 person signal is real and nonzero;
- E3.1 pose prerequisite succeeds where required for association;
- at least one real face observation produces the expected landmark count and valid image-plane geometry;
- at least one real left/right hand observation is produced when visible in the certification fixture, without manufacturing an absent hand;
- sidecar hashes and shapes match Blueprint refs;
- frame coverage and missing-value policy are correct;
- provenance identifies the exact runtime/model artifacts used;
- `identity_inference_performed == false`;
- `biometric_embedding_exported == false`;
- canonical schema and Bundle integrity validation pass.
