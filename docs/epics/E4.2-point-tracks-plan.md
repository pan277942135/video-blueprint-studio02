# E4.2 — Point Tracks / Sparse Motion Evidence

## Scope

E4.2 extracts anonymous image-space visual feature motion inside certified E4.1 person masks. It does **not** infer identity, biometrics, demographics, emotion, or cross-video correspondence.

Pipeline slice:

`PERSON_MASK -> POINT_TRACKS`

Dense flow, camera motion, body-local transforms, surface motion and micro-motion remain out of scope.

## Backend

Use the repository's existing OpenCV runtime only:

- Shi-Tomasi (`goodFeaturesToTrack`) for deterministic feature seeding;
- pyramidal Lucas-Kanade (`calcOpticalFlowPyrLK`) for adjacent-frame motion;
- no model weights, network download, or fallback model;
- points must remain inside the current E4.1 person mask;
- hard shot boundaries reset all feature state;
- lost/missing samples are explicit NaN/false and are never interpolated.

Point IDs are local evidence identifiers scoped to one anonymous character in one source video. Re-used storage slots are disambiguated by a monotonically increasing local `track_id` array.

## Manifest contract

E4.2 is initially emitted under `extensions.e4_point_tracks` because the canonical Character schema has no image-space point-motion slot and `surface_motion` is explicitly body-local. This avoids mislabelling pixel-space measurements as body-local evidence.

Each character may reference one NPZ sidecar containing:

- `positions_xy`: float32 `[frame, point_slot, 2]` in pixels;
- `valid`: bool `[frame, point_slot]`;
- `tracking_error`: float32 `[frame, point_slot]`, NaN when unavailable;
- `track_id`: int64 `[frame, point_slot]`, `-1` when invalid.

The TimeSeriesRef describes `positions_xy`; metadata names the companion arrays and declares the mask constraint, shot reset, algorithm, and slot semantics.

## Gates

E4.2 is PASS only when all of the following hold:

1. deterministic synthetic translation recovers the known displacement within tolerance;
2. full E4.1-mask -> E4.2 sidecar integration is schema-valid;
3. every emitted URI resolves to a physical artifact and checksum;
4. missing values remain explicit and no temporal interpolation occurs;
5. no point continuity crosses a hard shot boundary;
6. standard CI, Ruff and mypy pass;
7. a real-media certification demonstrates non-zero feature motion and validates the final Blueprint/Bundle evidence.

Merging the final PR into `main` remains a project-owner approval gate.
