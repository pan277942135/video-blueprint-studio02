# E3.2 Runtime Candidate — MediaPipe Face + Hand Landmarker

Status: **candidate / not approved / no real inference authorized**

Reviewed on: 2026-08-13

## Recommendation

Use MediaPipe Tasks Face Landmarker + Hand Landmarker as the first E3.2 runtime candidate, layered on the already-certified E2.2 RTMDet anonymous tracks and E3.1 RTMPose COCO-17 body pose.

Do **not** add RTMW to the first E3.2 slice. RTMW is a valid OpenMMLab whole-body candidate, but adding a second whole-body pose stack now would duplicate the already-certified body path and enlarge the certification surface without being required to satisfy the remaining face/hand contract. RTMW can be evaluated later as a fusion/quality upgrade if MediaPipe refinement proves insufficient.

## Official sources

### Face Landmarker

Official guide:
`https://developers.google.com/edge/mediapipe/solutions/vision/face_landmarker/python`

Official model overview:
`https://developers.google.com/edge/mediapipe/solutions/vision/face_landmarker/index`

Official latest float16 task bundle:
`https://storage.googleapis.com/mediapipe-models/face_landmarker/face_landmarker/float16/latest/face_landmarker.task`

Google documents the bundle as containing face detection, face mesh, and blendshape models. The face mesh output contains 478 landmarks. Video mode is supported.

For E3.2 initial scope:
- use landmarks only;
- `output_face_blendshapes = false`;
- `output_facial_transformation_matrixes = false` initially;
- convert normalized x/y to source-frame pixel coordinates for `Face.landmarks_2d_ref`;
- do not label model-relative z as calibrated camera/world 3D;
- do not export expression labels or infer emotion.

### Hand Landmarker

Official guide:
`https://developers.google.com/edge/mediapipe/solutions/vision/hand_landmarker/python`

Official model overview:
`https://developers.google.com/edge/mediapipe/solutions/vision/hand_landmarker/index`

Official latest float16 task bundle:
`https://storage.googleapis.com/mediapipe-models/hand_landmarker/hand_landmarker/float16/latest/hand_landmarker.task`

Google documents 21 landmarks per detected hand, handedness classification, image-coordinate landmarks, and model-provided world-coordinate landmarks. Video mode is supported.

For E3.2 initial scope:
- use image-coordinate landmarks converted to source-frame pixel XY;
- preserve handedness as a geometric association signal only;
- do not emit `landmarks_world_ref` until the Blueprint coordinate-space contract explicitly distinguishes MediaPipe hand-local/model-world coordinates from a calibrated scene/world coordinate system;
- absent/ambiguous hands stay absent rather than being inferred from pose symmetry.

## Runtime/API semantics

Preferred running mode: `VIDEO`, because the pipeline already owns a normalized CFR timeline and can supply monotonically increasing frame timestamps.

Default MediaPipe confidence settings documented by Google are 0.5 for detection/presence/tracking. E3.2 certification must not lower thresholds merely to force a pass; any project-specific threshold changes must be explicit in config/provenance and justified by real fixtures.

## Privacy boundary

Allowed:
- geometric face/hand landmarks attached to anonymous same-video `character_id`;
- left/right handedness used for track association;
- geometry-only quality metrics.

Not allowed:
- face recognition or face embeddings;
- identity matching or cross-video re-identification;
- real-person identification;
- age, health, emotion, sexual-attribute or other sensitive-attribute inference;
- exporting blendshape categories as semantic emotion labels.

## Integrity status

The official binary URLs have been identified, but their full SHA256 values are **not yet recorded**.

Reason: the current review environment could resolve the Google-hosted model URLs but could not retrieve the `application/octet-stream` payload for local hashing. No third-party or guessed hash is accepted.

Before approval, a dedicated GitHub Actions certification/bootstrap step must:
1. download each exact official URL;
2. compute the full SHA256 from the downloaded bytes;
3. persist URL + file size + SHA256 as workflow evidence;
4. copy the exact values into `docs/model-approvals/` only after project-owner approval;
5. make runtime startup fail closed unless the local file hash equals the approved full SHA256.

## Candidate acceptance prerequisites

- canonical `Face.landmarks_2d_ref` contract lands first;
- deterministic injected-backend tests pass without MediaPipe installed;
- MediaPipe package/runtime version is pinned and recorded;
- both `.task` artifacts receive full SHA256 locks;
- license/model-card records are captured from official sources;
- real face + hands certification fixture demonstrates nonzero legitimate outputs;
- E1 CI, E2 RTMDet certification, and E3.1 RTMPose certification remain green;
- explicit project-owner approval is obtained before real checkpoint inference.
